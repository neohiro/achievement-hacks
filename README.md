# 🏆 GitHub Achievement Hacks

> Agentic documentation, recipes, and automation for every GitHub Achievement.
> **By the [neohiro](https://github.com/neohiro) org. Made with love, automation, and a few gun emojis.**

---

## What is this?

This repository is the **canonical reverse-engineering of every GitHub Achievement badge** — what they look like, what they do, and **the mathematically friendliest, most user-friendly, network-cheapest, LLM-free way to earn each one** (and, where possible, an automation script that earns it for you).

It is also:

- A **living index** of all GitHub Achievements, including **frozen / deprecated** ones (Arctic Code Vault, Mars 2020) that GitHub no longer issues but still displays.
- A **forward-compatible** design — new achievements slot in without breaking the structure.
- A **public invitation** to GitHub themselves (see "A note to GitHub" at the bottom) to detect, prevent, or rate-limit the automation patterns we document.

We are not here to game a system in bad faith. We are here to:
1. **Document** what the badges are and how they work.
2. **Lower the barrier** for newcomers to earn the badges through real, organic work.
3. **Push the platform** to be more intentional about which automations it rewards.

### Running the checks

```bash
pip install -r requirements.txt

python _scripts/list_achievements.py --check    # meta.yaml vs. the markdown tables
python _scripts/grant_check.py                  # meta.yaml vs. the live profile
python tests/check_links.py                     # no dead links or anchors
python tests/check_workflows.py                 # CI config is valid
python -m unittest discover -s tests            # unit tests
python -m ruff check _scripts tests             # lint
```

All six run in CI on every change under `_achievements/`, `_docs/`, or
`_scripts/`, and weekly against the live profile.

### What is deliberately *not* here

Earlier revisions of this README advertised a `_scripts/grant_all.py`
("the lazy 'make them all appear' entry point"). **It does not exist and will
not be added.** A script whose purpose is to make badges appear without the
underlying work is not a research artifact, it is a lie told to other users at
scale. See [`_docs/AUTOMATION_ETHICS.md`](./_docs/AUTOMATION_ETHICS.md) for the
line we drew and why.

## Status legend

Every achievement tracks a `status` flag. See [`_docs/STATUS_LEGEND.md`](./_docs/STATUS_LEGEND.md) for the canonical meanings.

| Status | Meaning |
|---|---|
| `Not yet` | We have the recipe and verification, but no one in neohiro has earned it on this account yet. |
| `In progress` | Someone is actively working on it (e.g., waiting for stars, enabling Discussions). |
| `Earned` | Verified earned on the neohiro user account. Carries a `verified:` block in `meta.yaml`. |
| `Deprecated` | GitHub no longer issues this badge. Recipe is historical only. |
| `Unobtainable` | Requires enrollment in a program outside our control (e.g., Bug Bounty Hunter on GitHub's own platform). |

`Earned` is not a judgement call. Every status is checked against the live
profile by [`_scripts/grant_check.py`](./_scripts/grant_check.py), which exits
non-zero on any disagreement. Until 2026-10-03 that check did not exist and three
of the nine statuses were wrong; the method and the incident are written up in
[`_docs/VERIFICATION.md`](./_docs/VERIFICATION.md).

## How to add a **new** achievement (forward-compatibility)

GitHub ships new achievements irregularly. When they do:

1. Add `_achievements/<slug>/` (kebab-case, lowercase) with a `meta.yaml`
   matching [`_docs/ACHIEVEMENT_FORMAT.md`](./_docs/ACHIEVEMENT_FORMAT.md) and
   a `README.md` with all 11 required sections.
2. Run `python _scripts/list_achievements.py --write` to regenerate the tables
   above and in [`_docs/ACHIEVEMENT_INDEX.md`](./_docs/ACHIEVEMENT_INDEX.md).
3. Run `python _scripts/list_achievements.py --check` and
   `python _scripts/grant_check.py` to prove the catalog matches reality.
4. Open a PR.

Both catalog tables are generated; do not hand-edit them. CI fails if they drift
from `meta.yaml`. Before opening the PR, read
[`_docs/AUTOMATION_ETHICS.md`](./_docs/AUTOMATION_ETHICS.md) — a PR that adds a
badge-farming script will be rejected with an explanation.

## ⚖️ A note to GitHub

We respect the spirit of achievements. They exist to **celebrate real, sustained contribution** to the platform, and the rare/frozen ones (Arctic Code Vault, Mars 2020) are not earnable today — we don't pretend otherwise.

What we *do* document is that several achievements (Quickdraw, YOLO, Heart On Your Sleeve, the first tier of most others) are **mechanically trivial to acquire by automation**. We show the mechanism for each in [`SECURITY.md`](./SECURITY.md) so the weakness is on the record.

To be unambiguous: **this repository ships no automation that farms a badge.** The scripts in `_scripts/` are read-only (they fetch a public profile and render the catalog) or file issues against this repo. Techniques like mass-closing issues, mass-reacting to strangers' comments, or forging `Co-authored-by:` trailers are *described* as findings, not *implemented* as tools. The reasoning is in [`_docs/AUTOMATION_ETHICS.md`](./_docs/AUTOMATION_ETHICS.md).

**We invite the GitHub engineering team to:**

1. **Rate-limit** the surfaces that feed these achievements (e.g., require a human time-gap of N minutes for "close within 5 min" badges, weighted by account age).
2. **Tighten the bot detection** on reactions, co-author trailers, and issue close loops so the *cheapest* tiers can only be earned by accounts with real activity.
3. **Surface the badge's intent** — instead of "merged N PRs", display "merged N PRs across N distinct repos over N months" so the badge rewards breadth, not farming.
4. **Publish the actual threshold tables** for achievements like Heart On Your Sleeve and Open Sourcerer so honest users know what they're working toward.

If you'd like to chat about any of this, the maintainers are reachable via Discussions on this repo or by opening an issue.

— Creative Monkey at FrenzyPenguin Media

## Security vulnerabilities filed

6 vulnerability reports (VULN-001 to VULN-006) have been filed as GitHub Issues documenting the automation-surface risks in achievement awarding:

- [#1 VULN-001 Quickdraw](./issues/1) — sub-5-minute close loop
- [#2 VULN-002 YOLO](./issues/2) — admin-override merge bypass
- [#3 VULN-003 Heart On Your Sleeve](./issues/3) — mass reaction automation
- [#4 VULN-004 Pair Extraordinaire](./issues/4) — co-author trailer farming
- [#5 VULN-005 Pull Shark](./issues/5) — PR count farming
- [#6 VULN-006 Galaxy Brain](./issues/6) — self-answered Q&A farming

See [`SECURITY.md`](./SECURITY.md) for the full analysis and proposed defenses.
